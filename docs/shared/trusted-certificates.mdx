---
title: "Trusted certificates"
description: "Let Station and Scout verify internal HTTPS services signed by your own CA."
---

If an HTTPS service an app connects to uses a private CA, add that CA to the app's trust list. For example, Scout needs to trust Station's CA, and each app needs to trust its integration receivers' CAs. Each app keeps its own list.

This configures outbound trust. It doesn't enable HTTPS on either web UI or make your browser trust a private CA. For a complete reverse-proxy setup with existing certificates, hostname or IP addresses, and browser trust, see [HTTPS and homelab certificates](/shared/https).

## Upload from the UI

<Steps>
  <Step title="Open settings">
    Open **Edit Station Settings** in Station, or **Edit Scout Settings** in Scout.
  </Step>
  <Step title="Add the certificate">
    Under **Trusted Certificates**, upload your CA or root certificate as a PEM `.crt` file. Each app supports up to ten uploaded certificate files.
  </Step>
</Steps>

The app saves it under `/config/trusted-certs`, installs it into the container's trust store immediately, and reinstalls it every time the container starts.

<Note>
  Restart Scout after adding, replacing, or deleting a CA certificate so its existing Station upload/restore client uses the updated trust list. For a consistent refresh after CA changes, restart the affected app. This differs from changing `.env`, which requires recreating the container with `docker compose up -d`.
</Note>

## Add files directly

For automated deployments, drop `.crt` files into the app's persisted config folder before starting it:

```text
3to1go-station/config/trusted-certs/home-ca.crt
3to1go-scout/config/trusted-certs/home-ca.crt
```

<Note>
  Only CA or root certificates are needed, not each server's certificate. Files must end in `.crt`.
</Note>
