Station can send HTTP notifications from its **Integrations** dialog. Choose JSON events, plain text, or Discord messages; destination URLs and headers are encrypted and never returned to the browser after saving.

## Station events

| Event | When it fires |
|---|---|
| `upload-received` | Storage handling finishes, with `status` set to `ok` or `error`. |
| `unusual-upload` | A stored archive's size differs sharply from its history. See [Unusual sizes](/station/snapshots#unusual-sizes). |

Check the status in `upload-received`: receiving this event alone isn't proof of successful storage. Uploads rejected before the storage stage don't send it. Retrying an already finalized upload doesn't repeat events. Forced Scout uploads can trigger both Station events.

Filters can match the sending Scout ID, installation ID, job name, or source address. Filled filters all need to match. Source addresses are used for matching but aren't included in outgoing payloads. Unusual-size reasons require explicit opt-in to include details.

Scout has its [own events and destinations](/scout/notifications), including job failures that never reach Station. Station's [custom scripts](/station/hooks) still run around storage handling.
