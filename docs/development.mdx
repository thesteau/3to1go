Station and Scout are independently deployable apps in one repository. For deployment with published images, start with the [quickstart](/quickstart). This page covers working on the source.

Open normal development PRs against `main`, titled as Conventional Commits (`feat: …`, `fix: …`, `docs: …`). CI enforces this, and the title decides the next version. See [Releases](/releases#pr-titles-and-versions).

## Repository layout

| Path | Contents |
|---|---|
| `app/` | Go workspace, npm build tools and lockfile, base TypeScript config, and Docker build context |
| `app/station/` | Station's receiver API, storage logic, and web UI |
| `app/scout/` | Scout's scanning, encryption, upload, restore, and web UI |
| `app/shared/go/` | Wire protocol, authentication, HTTP helpers, certificates, hooks, ntfy templates, locks, configuration helpers, and web UI serving |
| `app/shared/ts/` | Browser scripts and types compiled into both UIs |
| `tests/` | TypeScript tests, grouped by area: `scout/`, `station/`, `shared/` (both UIs), `release/` (release automation), and `ci/` (CI tooling) |
| `deploy-example/station/`, `deploy-example/scout/` | Compose deployments using published images |
| `docs/` | Mintlify documentation |

`app/go.work` joins three Go modules: `app/station`, `app/scout`, and `app/shared/go`. Behavior specific to one app stays in that app's directory. Both `go.work` and `go.work.sum` live in `app/`. Git hooks, tests, and release scripts stay at the root. Go and Docker lint configuration lives in `app/`. The root `biome.jsonc` checks TypeScript and JSON across the apps, tests, and scripts. Run npm commands inside `app/`, or use `npm --prefix app` from the root. Go also discovers the parent workspace when commands run inside an app directory.

## Build locally

Use the Go version declared in the repository's `app/go.work` and module files, and **Node.js 24** for the frontend build. From the repository root, install the build tools and generate both UIs:

```sh
npm --prefix app ci
npm --prefix app run build
```

Then build an individual server from its app directory:

```sh
cd app/station
go build ./cmd/server
```

Use `scout` in place of `station` to build Scout.

## Run the tests

CI runs the Go and frontend tests on every PR, and the end-to-end test after each push to `main` or `prod`, since it builds both Docker images. You can run all three locally from the repository root. Go unit tests mock database calls and use in-memory store mocks for service tests. They don't open SQLite databases or connect to PostgreSQL. The Docker end-to-end test starts its own real database.

| Suite | Needs |
|---|---|
| Go unit tests | Go, Node.js 24, and `npm --prefix app ci` (Go embeds the generated UI) |
| Frontend and release tests | Node.js 24, `npm --prefix app ci`, and `git` |
| End-to-end test | Docker, `bash`, `curl`, and `jq` |

### Go unit tests

```sh
npm --prefix app run build
(cd app && go test ./shared/go/... ./station/... ./scout/...)

# One package, filtered by test name
(cd app/scout && go test ./internal/services/directories/ -run ListChildren -v)
```

CI also passes `-race`, which needs a C compiler. On Windows, tests that need symlinks, POSIX permissions, or `sh` report `SKIP`, but CI still runs them.

### Frontend and release tests

```sh
npm --prefix app test
```

This rebuilds both UIs and runs every `tests/**/*.test.cts` file. Tests are grouped by area:

| Folder | Covers |
|---|---|
| `tests/scout/` | Scout UI, such as the directory tree, file browser, and refresh loop |
| `tests/station/` | Station UI, such as the overview, saved keys, and snapshot decryption |
| `tests/shared/` | Behavior both UIs share |
| `tests/release/` | Release scripts and workflows |
| `tests/ci/` | CI tooling, such as the test report generator |

To run some tests without rebuilding every time, run `npm --prefix app run build` once (again after TypeScript changes), then:

```sh
node --test tests/scout/directory-tree.test.cts                            # one file
node --test "tests/station/**/*.test.cts"                                 # one area
node --test --test-name-pattern="directory tree" "tests/**/*.test.cts"    # by name
```

Quote globs so Node expands them, not your shell. Name new test files after their feature, end them in `.test.cts`, and put them in their area's folder.

### End-to-end test

`tests/integration/e2e.sh` runs PostgreSQL, Station, and Scout in Docker, takes a backup, and recovers it. Build the images it expects first:

```sh
docker build -t 3to1go-station-validation -f app/station/Dockerfile app
docker build -t 3to1go-scout-validation -f app/scout/Dockerfile app
bash tests/integration/e2e.sh
```

It uses host ports `16555` and `16556` and cleans up after itself. On Windows, run it from Git Bash or WSL.

### Test reports

`scripts/test-report.cts` turns results into a single HTML page with pass, fail, and skip counts and each failure's output. `npm --prefix app test` writes `reports/frontend-tests.html`. For Go tests, convert the `go test -json` output. The coverage page is optional:

```sh
mkdir -p reports && cd app/scout
go test -json -coverprofile=../../reports/scout-coverage.out ./... ../shared/go/... > ../../reports/scout-go-tests.json
node ../../scripts/test-report.cts go "Scout Go tests" ../../reports/scout-go-tests.json ../../reports/scout-go-tests.html
go tool cover -html=../../reports/scout-coverage.out -o ../../reports/scout-coverage.html
```

In CI, each test job writes a summary on its run page and uploads its reports as an artifact, kept for 14 days. Download it from **Artifacts** at the bottom of the run, unzip, and open the HTML file.

| Artifact | Contents |
|---|---|
| `frontend-test-report` | `frontend-tests.html` |
| `scout-test-report`, `station-test-report` | Test report, coverage report, and raw `go test -json` output |
| `e2e-container-logs` | Container logs, only when the end-to-end test fails |

## Linting and formatting

The CI workflow runs these checks on PRs and pushes to `main` and `prod`:

| Check | Tool | Config |
|---|---|---|
| Go | [golangci-lint](https://golangci-lint.run/) (`errcheck`, `govet`, `ineffassign`, `staticcheck`, `unused`) on each Go module | `app/.golangci.yml` |
| TypeScript and JSON | [Biome](https://biomejs.dev/) lint and format check | `biome.jsonc` |
| Workflows | [actionlint](https://github.com/rhysd/actionlint), which also shellchecks `run:` blocks | |
| Shell scripts | [ShellCheck](https://www.shellcheck.net/) | |
| Dockerfiles | [hadolint](https://github.com/hadolint/hadolint) | `app/.hadolint.yaml` |

Run the TypeScript checks with `npm --prefix app run lint`, and apply formatting and safe fixes with `npm --prefix app run fix`. Run golangci-lint from a module folder after `npm --prefix app run build`:

```sh
cd app/scout && golangci-lint run ./...
```

ESLint isn't used. TypeScript 7 has no JavaScript compiler API, which typescript-eslint needs. Biome parses TypeScript itself.

Biome doesn't flag unused top-level names or `let` globals in the UI folders. Those files share one global scope, so other files and inline `onclick` handlers use and reassign those names.

To run the same checks before each commit, install [pre-commit](https://pre-commit.com/) and run `pre-commit install` once. The hooks in `.pre-commit-config.yaml` need `npm --prefix app ci`, Go, and golangci-lint locally. The hadolint hook needs Docker.

## Repository maintenance

The CI workflow also checks Go formatting with `gofmt`, and runs these security checks:

| Check | Tool | Config |
|---|---|---|
| Committed secrets | [gitleaks](https://github.com/gitleaks/gitleaks) on the full git history | `.gitleaks.toml` |
| Code analysis | [CodeQL](https://codeql.github.com/) for Go, TypeScript, and workflows. Results appear under **Security** → **Code scanning** | |
| Go dependencies | `govulncheck` on all three Go modules | |
| npm dependencies | `npm --prefix app audit --audit-level=high`, including the frontend build tools | |

The security checks also run once a week, to catch newly reported vulnerabilities even when the code hasn't changed.

If gitleaks flags a fake value in a test, add it to the allowlist in `.gitleaks.toml`. If it flags a real secret, revoke it. Removing it from the code doesn't remove it from the git history.

Dependabot opens weekly update PRs for Go dependencies, npm tools, GitHub Actions, and Dockerfile base images. These PRs use Conventional Commit titles and go through the usual CI and review. Dependabot isn't set up to merge them automatically. See [Dependabot configuration](https://docs.github.com/en/code-security/reference/supply-chain-security/dependabot-options-reference) and [Go vulnerability management](https://go.dev/doc/security/vuln/) for details.

Report vulnerabilities using the repository's [security policy](https://github.com/thesteau/3to1go/blob/main/SECURITY.md).

## Frontend sources and generated files

Edit TypeScript in `app/station/static/ts`, `app/scout/static/ts`, or `app/shared/ts`. Each app compiles the shared scripts along with its own. They're classic scripts that share one global scope per app, so inline HTML handlers can call their functions. Don't add `import` or `export`.

Go embeds the generated `app/station/static/js` and `app/scout/static/js`, so generate them before `go build` or `go test` with `npm --prefix app run build` at the root, or `go generate ./...` in an app folder. Station's build also copies its pinned Zstandard decoder and ZIP library from npm into `static/js/vendor`, including their licenses; the file viewer serves them locally. They're gitignored. Don't edit or commit them or any other JavaScript (`.js`, `.mjs`, `.cjs`, `.jsx`, or source maps). CI rejects it.

For continuous compilation, use `npm --prefix app run watch` (Station) or `npm --prefix app run watch:scout` (Scout), then rebuild and restart the Go server to serve the new assets.

## Names in code

The UI, docs, and messages say **Scout key** and **Station token**. The code uses older names for the same things:

| In the UI | In the code |
|---|---|
| Scout key | encryption key: the `encryption` package, `encryption.key`, `/api/encryption-key`, `encryption_key`, `encryption_key_fingerprint` |
| Station token | Scout credential: `ScoutCredential`, `scout_credential`, `/api/credentials/...`, `credential`, `credential_hash`, the `scout_credentials` table |

Keep these code names. File names, API routes, JSON fields, database names, and the `3to1go_enc_*` browser storage keys are used by existing installs, so renaming them breaks saved settings, stored data, or connections between Scout and Station. Use **Scout key** and **Station token** in anything people read: UI text, docs, and error and log messages.

## Build with Docker Compose

`app/station/docker-compose.yml` and `app/scout/docker-compose.yml` build from this checkout, using `app/` as build context so shared code is included. Copy the app's `.env.example` to `.env`, configure it as in [Station installation](/station/install) or [Scout installation](/scout/install), then from that app's folder:

```sh
docker compose up -d --build
```

For published images, use `deploy-example/` instead.
