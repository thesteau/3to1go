title: "Scout notifications"
description: "Send backup events to HTTP services with protected destination secrets."
---

Scout can send HTTP notifications from its **Integrations** dialog. Choose JSON events, plain text, or Discord messages; destination URLs and headers are encrypted and never returned to the browser after saving.

## Scout events

| Event | When it fires |
|---|---|
| `job-finished` | A scheduled, manual-cycle, or forced job attempt finishes. Reports success, unchanged, empty, held, and failure states. Cancellation skips it. |
| `upload-finished` | A job uploads successfully, including **Force Upload**. |
| `unusual-backup` | A newly detected unusual backup is recorded. See [Unusual backups](/scout/unusual-backups). |

Choose `upload-finished` for success notices, `unusual-backup` for anomaly alerts, or `job-finished` to monitor all job outcomes. Selecting multiple events can send multiple messages for one attempt. Error and unusual-backup details require explicit opt-in.

Station has its [own events and destinations](/station/notifications). Use either app or both, depending on what you want to monitor. Scout's [custom scripts](/scout/hooks) still run around jobs in cycles; forced-job notifications don't change script timing.

## Set up a service

Follow the shared [Integrations guide](/shared/integrations) for setup, templates, and delivery limits. Detailed recipes are available for [Discord](/integrations/discord), [n8n](/integrations/n8n), [ntfy](/integrations/ntfy), and [generic HTTP POST](/integrations/http).
