title: "Restore"
description: "Bring a snapshot from Station back into a job's folder on Scout."
---

Scout can download a snapshot from Station, decrypt it with its own key, and extract it back into the job's folder.

<Frame caption="Station sends the sealed snapshot, and Scout opens it with its Scout key.">
  <img src="/images/gophers/restore.svg" alt="Station sends a sealed box to a Scout gopher, who opens it. Files fly out and go back into a house." />
</Frame>

```mermaid
sequenceDiagram
    actor You
    participant Scout
    participant Station
    You->>Scout: Preview Restore
    Scout->>Station: Download snapshot (latest or by fingerprint)
    Station-->>Scout: Encrypted archive
    Scout->>Scout: Decrypt and compare with the folder
    Scout-->>You: Files to replace and add
    You->>Scout: Restore These Files
    Scout->>Station: Download snapshot again
    Scout->>Scout: Decrypt and write files into the job folder
```

<Warning>
  Restore **overwrites** local files that are also in the snapshot. Files that aren't in the snapshot are left untouched. Check the preview before confirming.
</Warning>

## Restore the latest snapshot

<Steps>
  <Step title="Open Restore">
    On the job in **Selected Jobs**, click **Restore**.
  </Step>
  <Step title="Leave the fingerprint empty">
    An empty **Snapshot fingerprint** means the latest snapshot.
  </Step>
  <Step title="Preview">
    Click **Preview Restore**. Scout shows how many files the snapshot has, and how many would replace existing files or be added.
  </Step>
  <Step title="Confirm">
    Click **Restore These Files** to write the files into the job's folder. Search and the **All**, **Replace**, and **Add** filters only change what the preview shows. They don't pick a subset to restore.
  </Step>
</Steps>

## Restore a specific snapshot

Each snapshot's fingerprint is part of its filename on Station, and is shown as **FP** next to each snapshot in Station's UI:

```text
photos__2026-09-30T02-00-00Z__abcdef12.tar.zst
                              ^^^^^^^^ fingerprint
```

Enter those eight characters (or the full 64-character fingerprint) in **Snapshot fingerprint**, then preview and confirm as above.

Forced backups can share a fingerprint. When several snapshots match, Scout restores the newest. To get an older one, use its **Download** button in Station instead.

A job can only restore its **own** snapshots. You can't restore one job's snapshot into another job's folder.

## Restore requests from Station

Use this when Station still has a snapshot but the folder is gone from Scout. An admin clicks **Restore** on a snapshot in Station. Station only saves the request. Scout lists it under **Restore Requests**, and nothing is restored until someone accepts it in Scout.

```mermaid
sequenceDiagram
    actor Admin as You (Station)
    participant Station
    participant Scout
    actor Operator as You (Scout)
    Admin->>Station: Click Restore on a snapshot
    Station->>Station: Save request as pending
    Station-)Scout: Notify (a hint only)
    Scout->>Station: Get this Scout's requests with its Station token
    Scout-->>Operator: Restore Requests tab
    alt Accept
        Operator->>Scout: Accept, with a destination folder
        Scout->>Station: Mark accepted
        Scout->>Station: Ask for that exact snapshot
        Station-->>Scout: Send the encrypted archive
        Scout->>Scout: Decrypt and write files into the folder
        Scout->>Station: Mark completed
    else Reject
        Operator->>Scout: Reject
        Scout->>Station: Mark rejected
    end
```

<Steps>
  <Step title="Request it in Station">
    Save that Scout's key in Station, then click **Restore** on the snapshot. The key stays in your browser.
  </Step>
  <Step title="Open Restore Requests in Scout">
    The **Restore Requests** tab appears next to **Jobs** when Station has a request for this Scout.
  </Step>
  <Step title="Accept or reject">
    The folder name defaults to the job name in the request. Optionally rename it, then click **Accept**, or click **Reject**. For another device, enter the original snapshot’s Scout key before accepting.
  </Step>
</Steps>

- The destination is a folder directly under the scan root. Renames must be a single folder name, without path separators. It may be a folder that no longer exists, and Scout creates it.
- Scout only acts on requests it reads from Station itself. It never trusts the notification.
- If the restore fails, the request stays accepted and Scout shows **Retry Restore**. **Reject** dismisses it.
- A request lasts 1 hour, whether it's pending, accepted, or rejected. After that Station deletes it. **Accept** on an expired request fails and nothing is restored, so click **Restore** in Station again. **Reject** still works and dismisses it.

## Requirements

- Scout must be able to reach Station, with a valid Station token.
- Local job restores use the current Scout key. For a Station request targeting another device, provide the **original snapshot’s Scout key** on the receiving Scout. A missing or incorrect key prevents restoration.

<Note>
  After you [rotate the key](/scout/scout-key#rotate-the-key), Scout can no longer restore snapshots made with the old key, and Station's UI stops accepting the old key after Scout's next upload. Download any older snapshots you need **before** rotating.
</Note>

## Rebuilding a lost machine

Local job restores use Scout’s own **instance ID**, stored in `config/installation.id`. To restore onto a fresh installation, select that Scout as the target device in Station and provide the original snapshot’s Scout key when accepting on the receiving Scout. The key is used for that restore only; it does not replace the receiving Scout’s own key or get saved in Station.

**If you have the old Scout's whole `config` folder** (it includes `installation.id`, `encryption.key`, and the saved settings and Station token):

<Steps>
  <Step title="Put the config folder back">
    Place it next to `docker-compose.yml` before starting Scout for the first time.
  </Step>
  <Step title="Use the same Scout ID">
    Set `SCOUT_ID` to the old value in `.env`.
  </Step>
  <Step title="Recreate the job and restore">
    Create the job with the **same job name**, then use **Restore**.
  </Step>
</Steps>

**If you only have `encryption.key`**, download the snapshots from [Station's UI](/station/snapshots#download-a-snapshot) with that key, and extract them by hand:

```sh
tar --zstd -xf photos__2026-09-30T02-00-00Z__abcdef12.tar.zst -C /path/to/restore
```

<Tip>
  Backing up Scout's whole `config` folder, not just the key, makes this much easier.
</Tip>
