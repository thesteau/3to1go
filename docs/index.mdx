3to1go is a self-hosted backup system. Run one **Station** and a **Scout** on each machine you want to back up. Each has its own container, web UI, sign-in, and settings.

Like the gophers racing above, each Scout gathers the files from your chosen folders, packs them into archives, encrypts them with its Scout key, and carries them back to Station. Station stores the encrypted snapshots without decrypting them. To get files back, Scout fetches a snapshot, decrypts it, and restores the files. You can also download a snapshot through Station's UI, where your browser decrypts it with the Scout key you provide.

Your original files and Station's snapshots are two copies. For a third, sync Station's backup folder somewhere else. See [Storage and the 3-2-1 rule](/concepts/storage-and-3-2-1).

## The short version

<Steps>
  <Step title="Run Station on an always-on machine">
    A home server, NAS, or VPS.
  </Step>
  <Step title="Run Scout on each machine you want to back up">
    Give each a unique `SCOUT_ID` and a Station token minted by Station.
  </Step>
  <Step title="Choose folders in Scout">
    Each folder you save in Scout's Job Editor becomes a backup job. The editor stores it as a `.upload_dir` file in the folder, which you can also write yourself.
  </Step>
  <Step title="Back up and restore">
    Scout encrypts each job before upload. Browse and download snapshots in Station, or restore them from Scout.
  </Step>
</Steps>

## Why the name?

It references the [3-2-1 backup rule](https://en.wikipedia.org/wiki/Backup#Storage) (**3** copies, on **2** different media, with **1** offsite), reads as a countdown (3, 2, 1, Go!), and both apps are written in [Go](https://go.dev/).

## Why use 3to1go

- **Encrypted before upload.** Scout encrypts each archive before sending it to Station. Station's server never receives the Scout key.
- **Machines stay separate.** Each installation has its own instance ID, so machines never mix or prune each other's snapshots, even with the same `SCOUT_ID`.
- **Revocable Station tokens.** Mint and revoke Station tokens from Station's UI without deleting snapshots.
- **Jobs live with their folders.** Scout's Job Editor saves each job's settings in a `.upload_dir` file, which you can also edit directly.
