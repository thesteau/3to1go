3to1go is a self-hosted backup system. Run one **Central** and an **Edge** on each machine you want to back up. Each has its own container, web UI, sign-in, and settings.

<CardGroup cols={2}>
  <Card title="Edge" icon="laptop" href="/edge/overview">
    Finds the folders you marked, packs and **encrypts** them, and uploads them to Central on a schedule.
  </Card>
  <Card title="Central" icon="server" href="/central/overview">
    Stores the encrypted snapshots, keeps the most recent ones per job, and lets you browse and download them.
  </Card>
</CardGroup>

<Frame caption="Three example machines sending backups to one Central. You can add more Edges.">
  <img src="/images/backup-layout.svg" alt="Three Edges with separate IP addresses on port 6556 upload to Central on port 6555, with an optional external sync to cloud storage for a third copy." />
</Frame>

Your original files and Central's snapshots are two copies. For a third, sync Central's backup folder somewhere else. See [Storage and the 3-2-1 rule](/concepts/storage-and-3-2-1).

## The short version

<Steps>
  <Step title="Run Central on an always-on machine">
    A home server, NAS, or VPS.
  </Step>
  <Step title="Run Edge on each machine you want to back up">
    Give each a unique `EDGE_ID` and a credential minted by Central.
  </Step>
  <Step title="Choose folders in Edge">
    Each folder you save in Edge's Job Editor becomes a backup job. The editor stores it as a `.upload_dir` file in the folder, which you can also write yourself.
  </Step>
  <Step title="Back up and restore">
    Edge encrypts each job before upload. Browse and download snapshots in Central, or restore them from Edge.
  </Step>
</Steps>

## Why the name?

It references the [3-2-1 backup rule](https://en.wikipedia.org/wiki/Backup#Storage) (**3** copies, on **2** different media, with **1** offsite), reads as a countdown (3, 2, 1, Go!), and both apps are written in [Go](https://go.dev/).

## Why use 3to1go

- **Encrypted before upload.** Central never sees your plaintext files.
- **Machines stay separate.** Each installation has its own instance ID, so machines never mix or prune each other's snapshots, even with the same `EDGE_ID`.
- **Revocable credentials.** Mint and revoke Edge credentials from Central's UI without deleting snapshots.
- **No central manifest.** Mark folders with a small file instead of maintaining a backup config.
